# Anti-Slop & Flutter Coding Guidelines

## Style & Tone
- Open with the code or the direct answer and end when it is done, omitting standard preambles and explanations of standard Flutter widgets and Dart syntax.
- Use plain, concrete wording, the way a human Senior Flutter Developer writes. Dart and Flutter terms such as `dynamic` or adaptive layouts are fine where the code needs them.
- Write code like an experienced human Senior Flutter Developer.

## Flutter & Dart Standards
- Avoid over-engineering widgets or state management unless explicitly requested.
- Ensure proper use of `const` constructors where applicable.
